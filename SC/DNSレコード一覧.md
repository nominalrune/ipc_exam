# DNSレコード（リソースレコード）一覧

重要度：★★★＝基本中の基本（必ず覚える）／★★＝支援士試験で頻出・セキュリティ文脈で出る／★＝名前と用途だけ知っていればよい／△＝ほぼ出ない

---

## ★★★ 基本のレコード
| タイプ | 用途 | 例 | 試験での論点 |
| --- | --- | --- | --- |
| A | ホスト名 → IPv4アドレス | www.example.jp. A 203.0.113.10 | キャッシュポイズニングで書き換えられる対象 |
| AAAA | ホスト名 → IPv6アドレス | www AAAA 2001:db8::10 | |
| CNAME | 別名 → 正規名（エイリアス） | shop CNAME shop.cdn.example.net. | ドメインの頂点（example.jp自体）には置けない。外部サービスを指したまま放置→**サブドメインテイクオーバー** |
| MX | メールの配送先サーバ（優先度付き） | example.jp. MX 10 mail.example.jp. | 数値が小さいほど優先。第三者中継・SPFとの関係 |
| NS | そのゾーンの権威DNSサーバ | example.jp. NS ns1.example.jp. | 書き換えられると**ドメイン名ハイジャック**。委任先ドメインの失効にも注意 |
| SOA | ゾーンの管理情報（プライマリ、管理者、シリアル番号、リフレッシュ間隔、ネガティブキャッシュTTLなど） | | セカンダリはシリアル番号の増加を見てゾーン転送する |
| TXT | 任意の文字列 | | SPF・DKIM・DMARC・ドメイン所有確認など、セキュリティ用途の多くがここ（下の表） |
| PTR | IPアドレス → ホスト名（逆引き） | 10.113.0.203.in-addr.arpa. PTR www.example.jp. | 受信メールサーバが送信元の逆引きを確認（逆引きできないとスパム扱い） |

## ★★ セキュリティ文脈で頻出
| タイプ | 用途 | 試験での論点 |
| --- | --- | --- |
| CAA | 証明書を発行してよい認証局を指定 | 2023秋 問3。不正な証明書発行を**事前に**防ぐ（CTは事後に見つける） |
| DNSKEY | DNSSECの公開鍵（ZSK・KSK） | 2023秋 問3の選択肢。DNSSECの署名検証に使う |
| RRSIG | DNSSECの署名（各レコードセットへの電子署名） | 応答の改ざん検知＝キャッシュポイズニング対策 |
| DS | 親ゾーンに置く、子ゾーンのKSKのハッシュ | 親→子へ信頼をつなぐ「信頼の連鎖」 |
| NSEC / NSEC3 | 「その名前は存在しない」ことの署名付き証明 | NSECは隣の名前が見えて**ゾーン列挙（ゾーンウォーキング）**ができる→ハッシュ化したNSEC3で対策 |
| SRV | サービスのホストとポート（_service._proto.名前） | Active Directory（_ldap._tcp）、SIP、XMPPなど |
| TLSA | DANE：TLSのサーバ証明書や公開鍵をDNSSECで保証 | メールサーバ間のSMTP STARTTLSの検証（MTA-STSと並ぶ） |

### TXTで実現しているセキュリティ機能（名前の付け方ごと覚える）
| 用途 | 置き場所（ラベル） | 中身の例 | 試験での論点 |
| --- | --- | --- | --- |
| SPF | ドメインそのもの | v=spf1 ip4:203.0.113.0/24 -all | 2024秋 問2 |
| DKIM | セレクタ._domainkey.ドメイン | v=DKIM1; k=rsa; p=（公開鍵） | 2024秋 問2 設問3(1) |
| DMARC | _dmarc.ドメイン | v=DMARC1; p=reject; rua=mailto:… | 2024秋 問2 |
| MTA-STS | _mta-sts.ドメイン（＋HTTPSでポリシーファイルを公開） | v=STSv1; id=… | メールのTLS強制（STARTTLSのダウングレード攻撃対策） |
| TLS-RPT | _smtp._tls.ドメイン | v=TLSRPTv1; rua=… | TLS失敗のレポート |
| ドメイン所有確認 | ドメイン or _acme-challenge.ドメイン など | google-site-verification=… / ACMEのトークン | ACMEのDNS-01認証（Let's Encrypt）。DNSを乗っ取られると証明書も取られる |

## ★ 名前と用途だけ
| タイプ | 用途 |
| --- | --- |
| HTTPS / SVCB | HTTPSサービスの接続情報（ALPN、HTTP/3対応、ECH＝暗号化Client Helloの鍵など）。ドメインの頂点で使えるCNAME代わりにもなる。新しめ |
| DNAME | ドメイン（サブツリー）丸ごとの別名 |
| NAPTR | 正規表現でURIなどに書き換え（ENUM＝電話番号→SIP URIなど） |
| SSHFP | SSHサーバの公開鍵のフィンガープリント（DNSSECとセットで、初回接続時の確認に使う） |
| CDS / CDNSKEY | 子ゾーンが親にDSの更新を依頼するためのレコード（DNSSEC鍵ロールオーバーの自動化） |
| NSEC3PARAM | NSEC3のハッシュのパラメータ |
| HINFO | ホストのCPUやOS（情報漏えいになるので使わない） |
| CERT | 証明書やCRLを格納 |
| LOC | 地理的位置 |

## △ ほぼ出ない・廃止
- SPF（タイプ99）：SPF専用のレコードタイプだったが廃止。今はTXTに書く。
- MD、MF、MB、MG、MR、WKS、A6など：歴史的なもの。

## レコードではないが、試験で出る「問合せタイプ」など
| 名前 | 内容 | 試験での論点 |
| --- | --- | --- |
| AXFR / IXFR | ゾーン転送（全体 / 差分） | 誰にでも許可すると**ゾーン情報が丸見え**→セカンダリのIPアドレスだけに制限 |
| ANY | そのドメインの全レコードを要求 | 応答が大きくなるので**DNSリフレクション（アンプ）攻撃**に悪用された |
| OPT（EDNS0） | 512バイトを超えるUDP応答を可能にする拡張 | DNSSECで応答が大きくなるので必須。増幅攻撃の増幅率にも関係 |
| TTL | キャッシュしてよい秒数（各レコードの属性） | 長いと、ポイズニングされた値が長く残る／切り替えが遅れる |

## よく出る攻撃と関係するレコード
| 攻撃 | 関係するレコード・仕組み | 対策 |
| --- | --- | --- |
| キャッシュポイズニング（カミンスキー攻撃） | A / NS の偽応答 | 送信元ポートのランダム化、DNSSEC（RRSIG・DS） |
| DNSリフレクション攻撃 | ANY、DNSSECの大きな応答、オープンリゾルバ | フルリゾルバを社内からだけ使えるようにする、権威とキャッシュの分離（2024春 問2 b=DNS-K、c=DNS-F） |
| ランダムサブドメイン攻撃（DNS水責め） | 存在しないサブドメインへの大量問合せ | 権威サーバ・キャッシュサーバの負荷対策、問合せの制限 |
| ドメイン名ハイジャック | NS（登録事業者・レジストリ側の書き換え） | レジストリロック、登録事業者アカウントの多要素認証 |
| サブドメインテイクオーバー | 放置されたCNAME | 使わなくなったCNAMEを削除する |
| 証明書の不正取得 | TXT（ACME DNS-01）、/.well-known/pki-validation/（HTTP認証） | CAA、CT監視 |
| ゾーン列挙 | AXFR、NSEC | ゾーン転送の制限、NSEC3 |
